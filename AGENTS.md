# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project Type

This is a [Zensical](https://zensical.org/) site (successor to MkDocs Material) published from `main`.
It is configured with Zensical's native `zensical.toml` (migrated from `mkdocs.yml`).

## Start Here

- Read `README.md` for project identity.
- Read `zensical.toml` before changing docs/theme/plugins.
- Primary authored content is under `docs/` (currently mostly `docs/index.md`).

## Environment And Commands

Use the repo-local virtual environment when available.

```bash
source env/bin/activate
pip install -r requirements.txt
```

Common commands:

```bash
# local preview
zensical serve

# production build validation
zensical build --strict
```

The two downloadable CVs (US Letter) are generated by a standalone script with Jinja2 + XeLaTeX
(not Zensical):

```bash
python cv/build.py      # renders docs/assets/doc/sandmann-academic.pdf and sandmann-resume.pdf
```

It needs TeX Live with XeTeX (`CV_XELATEX` overrides the engine path). Templates are
`cv/templates/academic.tex.j2` and `resume.tex.j2` (LaTeX-safe Jinja2 delimiters `((( value )))`,
`((* block *))`; values are LaTeX-escaped automatically). Fonts load by path from `cv/assets/fonts/`.
The build fails if the résumé exceeds one page or a column overflows (`CV_ALLOW_OVERFLOW=1` to inspect),
is reproducible, and strips the photo's EXIF/GPS metadata. Inspect the result as images after layout
changes (`gs -sDEVICE=png16m -r100 -o p%d.png <pdf>`).

Edit `cv/data/cv.yml` (single source of truth) to change CV content — never the PDFs. CI runs
`cv/build.py` and commits the PDFs on push when they change.

CI/CD reference:
- Workflow: `.github/workflows/main.yaml`
- CI installs `requirements.txt` and TeX Live (XeTeX), builds the CV PDFs, runs `zensical build --strict` with the commit date written into `zensical.toml`, and
  force-pushes `site/` to the `gh-pages` branch with `ghp-import` (GitHub Pages serves from `gh-pages`).

Only run deploy commands when explicitly requested.

"Last update" date — WORKAROUND (gambiarra), to be removed when a viable alternative exists: Zensical does
not support `git-revision-date-localized` yet. TOML has no env-var substitution, so CI
rewrites `last_update = ""` in `zensical.toml` (`[project.extra]`) with the pushed commit's date right before
the build (not committed) → `overrides/partials/source-file.html`. Once Zensical supports the plugin natively,
enable it and delete the override, the `last_update` entry and the CI `sed` step.

## Editing Conventions

- **Rule — a CV change updates every derived copy.** Whenever any CV content changes (a role, date,
  title, degree, publication, contact…), update all of them in the same change: `cv/data/cv.yml` (→ both
  PDFs), `docs/index.md`, `overrides/partials/structured-data.html` (JSON-LD), `docs/llms.txt`, the
  `description`/`site_description` and `cv/og_card.py` (headline, photo) when affected — and list the
  matching edits for the external profiles (ORCID 0000-0001-7758-695X, LinkedIn, Glassdoor/Indeed on the .com sites, all in English, professional e-mail hsandmann@ieee.org — the
  Glassdoor profile holds the résumé PDF, so re-upload it), which are only changed
  with the user's go-ahead.
- Prefer editing source docs in `docs/` and configuration in `zensical.toml`.
- Keep custom styling in `stylesheets/extra.css` instead of inline styles when practical.
- Do not edit files under `env/` (local virtual environment artifacts).
- Keep plugin/theme changes in `zensical.toml` synchronized with `requirements.txt`.
- Theme uses `variant: modern`; the logo is the inline `material/school` icon (`theme.icon.logo`). `overrides/partials/header.html` is a copy of Zensical's
  header plus the two CV buttons — keep it in sync on Zensical upgrades.
- `docs/index.md` uses the HTML components styled in `extra.css` (`cv-hero`, `cv-stats`, `cv-entry`,
  `cv-rows`, `cv-pubs`, `<details class="cv-more">`); copy an existing entry when adding one.
- SEO/sharing/analytics live in `overrides/main.html` and `overrides/partials/structured-data.html`
  (JSON-LD), plus `docs/llms.txt` and `docs/robots.txt`. Keep them factual and in sync with `index.md`;
  never add hidden text or instructions aimed at crawlers or AI screeners. Analytics (GoatCounter) and
  search-console verification turn on by filling the empty keys in `zensical.toml` `[project.extra]`.
  Regenerate the share image with `python cv/og_card.py` (from `cv/`).
- `docs/previous/` holds frozen static copies of earlier sites (`2026/` pre-redesign, `2017/` sandmann.sdf.org),
  marked `noindex`; the footer links `2026` to its copy and `2017` to the live sandmann.sdf.org (the
  2017 copy is an unlinked backup). Zensical copies them verbatim but skips dot-files.
- Supporting files live in `docs/archive/` (`documents/`, `academic/`, `publications/`, `ijcnn/`, `media/`, `web/`),
  named `YYYYMMDD-<issuer/outlet>-<subject>[-<type>].<ext>` (lowercase, hyphens, date = issue date).
  Only git-tracked files are published; `docs/archive/**` is gitignored, so new files stay private
  (local + Cloudflare R2 bucket `hsandmann-github-com`) unless added with `git add -f`. Never deploy from a
  local build (it contains the private files). The generated CVs stay in `docs/assets/doc/` (fixed names).

## Validation Checklist

Before finishing:

1. Run `zensical build --strict`.
2. If the CV changed, run `python cv/build.py` and look at the PDFs as images.
3. If content/layout changed, run `zensical serve` and spot-check affected pages.
4. If dependencies changed, ensure `requirements.txt` reflects them.
